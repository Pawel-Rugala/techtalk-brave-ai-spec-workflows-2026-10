02 · Spec-driven development

So what actually is a spec?

Spec ≠ a 40-page Word doc

A spec is concrete enough that another developer or an agent can implement the feature without asking 20 questions.

specs/create-payment.md# Create Payment ## Goal User can create a payment for an existing invoice. ## API POST /payments { invoiceId, amount, clientRequestId } ## Business rules - invoice must exist - invoice cannot already be paid - amount must equal outstanding balance - operation must be idempotent ## Events PaymentCreated · PaymentFailed ## Error cases 404 INVOICE_NOT_FOUND · 409 PAYMENT_ALREADY_EXISTS ## Acceptance criteria - [ ] duplicate clientRequestId → same payment
[9:00–11:00] Say it upfront: a spec is NOT 40 pages in Word. It's markdown in the repo, next to the code. The test: can another developer or an agent implement it without asking 20 questions? Show the sections: goal, API, business rules, events, errors, acceptance criteria.
02 · Spec-driven development

Good spec vs bad prompt

PROMPT

Add payment endpoint.

…and the agent guesses the rest.

SPEC
POST /payments
Preconditions: invoice exists · status = OPEN
Invariant: payment.amount ≤ invoice.remainingAmount
Idempotency: clientRequestId
Concurrency: optimistic lock on invoice
Side effects: PaymentCreated event
Failure modes: 404 · 409 · 422 → retry only 5xx

AI doesn't need more creative prompts.
AI needs less ambiguity.

[11:00–12:30] Left — what we hand the agent today. Right — the same thing, with nothing left unsaid. Every line of the spec closes one stamp from the previous example. Punchline: we don't need better prompts, we need less ambiguity.

04 · What can go wrong

Anti-patterns

#1

Prompt-driven development

"make it work""fix tests""implement JIRA-123"
…with no context.

#2

Giant autonomous agent

One agent: requirements, architecture, implementation, review, tests, deploy. Sounds cool — zero separation of responsibilities.

#3

AI reviewing its own assumptions

The agent implements its own interpretation, then reviews it itself: "Looks good ✅"
Review against the spec, not against the code.

#4

No deterministic validation

The only check: "Claude says it looks good"
You need: compiler · types · tests · schemas · contracts · linters · security checks.

[23:30–24:30] So this doesn't sound like an AI utopia. The four things I see most often. Especially #3: an agent reviewing its own assumptions will always say "looks good".
